# 独立本地轮岗测试时钟

此目录是本地扩展，不属于正式发布白名单。正常 `app.main:app` 不导入它，不挂载其接口，也不注入控制条。复用当前轮岗配置时钟、动态预排、事务、日志和每秒后台推进，没有另一套轮岗引擎。

## 启动

在仓库根目录执行：

```powershell
& backend/.venv/Scripts/python.exe local_tools/rotation_clock/run.py --demo --port 8011
```

打开 `http://127.0.0.1:8011/rotation-board`。只监听本机，不占用或重启8000端口。8011已被使用时，请换一个端口，不要结束原服务。

- 演示员工：`9720001`至`9720012`，密码同上；个人待办在工作台的待办中心。
- 大屏：`6666666`，密码 `1243`，登录后进入 `/rotation/screen`。
- 示例工作日：2026-11-05；12名纯模拟人员，两条线路，最晚班次到次日02:00。
- 默认独立数据目录：仓库的 `tmp/rotation-simulator/data`。可用 `--data-dir` 指定一个全新空目录。禁止接入已有数据库；已有目录必须带本模拟器创建且与绝对路径一致的标识。运行环境的正式路径、符号链接越界检查继续有效。

首次 `--demo` 初始化模拟人员和导入格式班表；以后复用原模拟器数据，不改已有密码、配置或重新生成运行日。可在此独立应用的名单和每日班表中上传自己的测试班表。此入口从不读取或复制生产数据库、现有本地业务数据库。

## 操作

控制条只给本地应用内具备管理权限的账号显示，在看板标签栏右侧，窄屏自动换行。包括日期、秒级时间、应用后暂停、暂停/继续、1/5/10/30/60倍速和快进1/10分钟。大屏及个人页显示同一后台模拟时间和倍速，但不能调时。

调时修改的是该景点圈的共享轮岗时钟，后台、看板、个人待办和大屏一致。暂停仍能本人确认餐休/上岗、人工拖拽，轮岗日志的业务时间使用当前模拟时刻。登录、会话、角色和临时授权仍按真实时间，不改变系统时钟。

倍速及快进均调用当前引擎按业务边界推进。不会代替员工确认；未确认满3分钟正常进入异常池。首班保留已确认的自动开班例外。闭园后继续到最晚班次，跨午夜仍保持原轮岗工作日；标识同时显示实际模拟日期。

回拨只改时钟，不倒放引擎、不回撤已执行记录、不复活已结束轮岗日。此前执行形成的站位和累计记录继续保留；需要干净重测时使用下面独立操作。

## 从当天初始班表重新开始

此按钮与调时间分开：先确认清理范围，再输入当前**轮岗工作日**，第二次确认后执行。午夜后仍清理原工作日，不是自然日。

只清理当前景点圈、当前工作日的轮岗测试结果（站位/任务/事件/计时/待办/轮岗快照），恢复发布时保存的初始班表，产生新的确认代次，暂停并恢复1倍速。起点通常为04:00；首班更早时使用首班时刻。

保留原班表与上传记录、保存配置、其他日期、其他景点圈和其他业务表。没有初始班表或不是新版轮岗日则拒绝重测；失败回滚。当前运行中的定岗也仅在该次重测事务中清除。

## 验证与发布隔离

```powershell
& backend/.venv/Scripts/python.exe -m pytest backend/tests/test_rotation_local_clock.py -q
node backend/tests/rotation_local_clock_ui.cjs
```

浏览器检查需要能找到项目已有Playwright，并已安装对应浏览器。可用 `ROTATION_CLOCK_ENGINES=edge` 先做单浏览器检查；默认Edge、WebKit、Firefox。各检查自行创建独立数据和随机端口，不连接已运行服务。

新增调时接口为 `/__local/rotation-clock`，仅由本入口挂载，管理权限、独立目录和本地环境均须通过检查。测试拒绝自动确认类快捷操作，并核验实际 `release_sources()` 清单不含此目录、扩展资产和新增测试。正式后端、HTML、静态资源无需改动，不能通过显示隐藏按钮来开启本扩展。
