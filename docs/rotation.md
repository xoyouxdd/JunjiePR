# 轮岗看板

> 现行轮岗规则、动态预排、人员池与特殊优先级见[动态预排说明](rotation-forecast-v2.md)。

## 当日持续定岗（2026-10-24，本地）

- 正式看板点击一个有在岗人员的岗位，选择“设置持续定岗”，可填写不超过100字的说明。TR、主管/TA主管、经理/TA经理沿用既有看板操作权限；CM和轮岗专用临时身份仅能看到状态，不能设置或取消。
- 定岗绑定当前人员与当前岗位；其他岗位跳过定岗岗继续按原顺序轮转。所有可轮换岗位均被定岗时，不再往该线安排普通推岗；旧的替换去向作废重算，旧的本人确认不能执行改变后的路线。
- **定岗优先于当日下班、计划出圈、推7点、计划撤岗和闭园**。这些时间到达时不自动解除，真实站岗时长持续累计。直接拖动、撤岗、移出或停用含定岗人员的线路，须先取消定岗；更改岗位顺序时岗位及其在岗人员、定岗状态一起移动。
- 取消后使用当前实际时间：已到下班时间则下班；当前处于计划出圈时段则出圈；闭园后按原闭园下线流程处理；已过期的出圈时段不补做，仍可轮转的保持当前岗位，继续正常推岗。计时不重置，不补推之前错过的轮次。
- **仅当日有效，00:00自动结束**，不把定岗带入次日班表；零点收尾写入自动结束记录。定岗未取消时不能强制重新生成该日班表绕过定岗。
- 看板、个人线路和待办显示定岗标识、开始时间与说明；正式记录保存设置/取消操作者，日内历史快照保存对应状态。复用原JSON状态、实时通知和事务，无新增权限、数据库表或PR计分规则。

验证：`test_rotation_post_holds.py`、`rotation_post_holds_ui.cjs`，并回归正式权限和事务测试。浏览器使用隔离合成数据及真实API，不代表手机真机验收。

## 正式员工入口（本地实现，部署后生效）

工作台“轮岗看板”直接使用当前员工登录身份；不选择模拟工号，不使用轮岗专用账号。按员工当前景点圈隔离：CM仅查看当日看板，可在待办中心确认本人“待上岗、待休息（吃饭）”；TR可操作当日看板，不提供每日班表、名单、记录、设置；主管、TA主管、经理、TA经理可使用全部业务功能。角色或账号状态变化后服务端重新核验，不能仅靠隐藏按钮控制权限。

正式页面 `/rotation-board`、API `/api/rotation-board/*`。正式记录存入同一业务数据库内独立的 `formal_rotation_*` 表；复用规则引擎与事务、另用运行缓存和版本号，不复制测试名单、模拟会话、计时、待办或日志。首次创建正式配置时仅沿用原线路/岗位和参数，时钟始终从真实日期开始。班表须重新上传，工号须属于本圈在职员工，姓名统一使用系统员工档案。正式页面没有测试时钟、测试重置或模拟凭据设置。

正式本人待办在行动中心展示；未到休息结束或出发窗口不可确认，休饭选择与强制饭点沿用原规则。确认携带步骤标识，同一步骤重复点击只返回原结果，变化后旧标识409，网络结果不明时先查询确认结果、再使用同一标识重试。成功后刷新待办数量并显示相关整条线路的岗位与当前人员，不把前往途中冒充已到岗。看板通过实时事件与轮询补偿同步，待办每5秒及切回页面时同步。

正式管理中的加撤岗、人员移动和岗位顺序调整保留影响预览与版本校验；TR不能借此读取历史或修改配置。操作记录保存真实员工ID和姓名。所有正式表包含在原SQLite整体备份中；未新增外部数据库。

## 休息室大屏

休息室大屏从登录页使用设备账号登录，页面地址仍是 `/rotation/screen`。设备读取正式看板数据，可确认班前已到、去休息和去轮岗。状态、操作、回执、事件流和退出由 `/api/rotation-screen` 提供。员工现场调整继续在正式看板使用各自账号。大屏专用账号及会话存于轮岗身份表。

热力追踪正式经理或管理范围包含热力追踪的正式经理，可在「轮岗看板 → 设置 → 休息室大屏账号」查看账号并重置密码。密码重置后，该账号已登录的大屏需要重新登录。

## 使用流程

1. 「名单」上传 ZTP 周班表或标准模板（工号、姓名、日期、班次、备注）。按天上传的覆盖按周上传的同一天。
2. 有当日班表时，03:00自动生成当天预排，主管/经理可在看板拖拽未到班次人员（交换预排岗位），点击岗位加撤岗；未到班次不计时。也可在「每日班表」手动生成当天草稿检查后发布。需要调时或重演时使用[独立本地模拟器](../local_tools/rotation_clock/README.md)。

### 每日班表与历史回看

原「初始化」入口改为「每日班表」，沿用主管/经理权限。可选月份、日历日期，展开查看上传班表；选择日期只改变回看范围。未来日期有上传班表时自动准备该日草稿，岗位和人员均可跨线交换，支持拖拽及依次点选两处后确认；岗位交换连同预排人员移动。手机支持触摸拖拽；7点岗仍只允许07:00班次人员，空岗也可作为人员交换目标。

未来预排保存后不产生在线计时、职责或个人待办，到该日03:00启用并保留人工调整。重新上传班表不会静默覆盖人工安排：标记原预排已过期，暂停自动启用，需重新生成并核对。已有手动当天草稿继续由主管检查后发布。当天运行中的闭园时间在「看板」调整。

每日班表使用与看板相同的线路、岗位及人员区布局。今天已启用但首个班次尚未开始时，仍可在每日班表拖拽，和看板共享同一份预排；仅时钟推进不影响编辑校验，其他人实际调整则须刷新。首个班次开始前保存整份开班安排快照，此后每日班表（包括今天及往日）固定只读；看板的人员、岗位及后续班次调整不会反写快照，实际变化到轮岗记录查看。未开始班次不提前计时，未来预排不提前产生职责或待办。

开班快照与运行状态在同一事务内保存，失败会一起回滚。旧日期没有开班快照时，优先展示当时保存的初始预排，其次最早状态记录，最后才是仅存的末次状态，并明确标注来源；不能冒充首班快照。未启用的往日草稿仅作为预排回顾；首班之后才启用的日期标明实际启用时刻，不冒充此前已保存的首班快照。原按时间读取运行快照的接口保留兼容，不作为每日班表页面的默认展示。

每日编辑带该日版本，旧版本返回409并刷新，避免多人修改覆盖。岗位交换跟随岗位移动原安排；交换仅影响该日。管理人员通过 `/api/rotation-board/daily` 按月查日期，通过 `/api/rotation-board/daily/{date}?at=HH:MM` 回放已保存的状态。

「记录」可查实际操作日志和个人本周轮岗记录。历史回放只读取正式库已有的原始预排、开班快照、时间快照和记录状态。选择指定时刻时取该时刻之前最近一份已保存的快照。回放不会生成旧规则安排、推进当日状态或改写数据。

## 实时同步

正式看板和休息室大屏通过各自的 SSE 接口推送变化后的版本号，页面收到后重新拉取；断线时每5秒轮询，正常时每15秒核实最新状态，回到前台及恢复联网也刷新。倒计时在页面本地每秒计算。顶部显示实时同步/定时同步/连接中断及最后更新时间；旧响应不能覆盖较新的响应。

确认请求12秒超时，结果不明确时保留待核实标识（当前页内存和本标签页会话存储），暂停继续确认并查询服务端结果；不会离线排队执行轮岗。核实已成功则提示成功，未成功则获取最新安排后允许本人重新确认。网络恢复后自动重连和补拉；轮岗页需保持前台才能获得持续画面更新，后台手机不保证秒级刷新。前台正常网络下以1～2秒同步为现场验收目标，尚不代表已完成真实场地的多人/弱网验收。

操作、后台推进及查询时自动预排共用服务事务：持锁加载私有状态副本，完成数据库提交后才发布缓存和版本。失败回滚数据库并丢弃副本。当前锁和缓存属于单进程，不能据此开启多个 worker。

动作参数校验岗位索引和线路标识，负索引、越界岗位及错误参数返回业务错误。线路标识必须是非空字符串且不能包含 `#`；配置中的岗位时间和数值参数在保存前检查，避免错误配置保存后阻断预排。

## 旧轮岗退役与本地模拟

正式运行、调度和每日生成使用规则版本2。旧版运行日可查看，旧版预排需要按现行规则重新生成并核对才能启用。升级应安排在当日轮岗结束后。若正式库仍有旧版在途日，旧日保持只读，需核对当日记录和现场交接，再启用现行安排。

旧沙盒页面、模拟账号入口、临时授权及 API 已退役，后台只推进正式表。历史正式记录读取 `formal_rotation_*`。旧沙盒数据在原表中独立保留。正式大屏继续使用现有设备身份表。表结构见[SQLite 表结构](sqlite-schema.md#轮岗)。需要调整时间或重演时，使用[独立本地模拟器](../local_tools/rotation_clock/README.md)与隔离数据目录。

## 休息室大屏布局

顶栏突出当前时间及待处理人数，点击数字可直达对应区域。有可签到班次时会单列「班前签到」。待上岗按确认截止时间排列并显示剩余时间，到点等待服务端状态更新。已超时人员按超时时间排列并直接显示。待确认休息优先展示有记录且等待较久的人员，餐休列表按结束时间排列。

横屏左侧按线路查看岗位和人员，右侧优先显示待处理任务。窄屏先显示待处理任务，再显示线路。待确认休息、待上岗和班前签到先展示完整行，其余人员可展开后随页面一起滚动。「其他人员」默认收起，可展开查看待到班、已下班等人员。实时刷新会保留展开状态及仍可用的操作焦点。

本地运行 `node backend/tests/rotation_tablet_ui.cjs --serve` 后，可访问 `http://127.0.0.1:18112/` 查看满班布局。预览使用实际大屏渲染和虚构数据，操作按钮只显示演示提示。浏览器回归覆盖从 390×844 到 1920×1080 的七种布局，其中 1080p 夹具核对九条线路及 54 个岗位的首屏可见性。


## 现场调整

正式看板按员工权限提供现场预览和调整，保存实际操作身份。拖拽人员、调整岗位及交换顺序沿用现行任务规则，提交前核对受影响人员及路线。餐休区人员恢复派发、超时转接和岗位调整的操作说明见[动态预排说明](rotation-forecast-v2.md)。
