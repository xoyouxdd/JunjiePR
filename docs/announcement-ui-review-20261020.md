## 真实功能与权限

审查了`announcements.js`全部列表、阅读、收藏、签收、消息、交接、记录、培训、发布、素材及授权流程，以及`announcement-state.js`、`announcement-media.js`、公共导航、表单保护、弹窗、API和样式。授权依据为现有公告路由、领域服务和`options`响应。

| 功能 | 沿用的真实条件 | 新入口 |
| --- | --- | --- |
| 待查收／已查收／收藏／消息 | 本人接收记录、收藏与通知 | 四个固定个人栏目 |
| 小组／管理 | `can_follow`、`can_publish`或`can_admin` | 按原角色标签进入工作区 |
| 培训跟进 | `can_train`，服务端另校验培训师授权 | 仅有此工作区时直接进入 |
| 交接 | `can_handover`或`can_admin` | 工作区菜单，保留共同负责人和接受流程 |
| 授权 | `can_admin` | 最高权限工作区 |
| 发布 | `can_publish` | 标题旁按钮；无权限不渲染，也不渲染发布草稿入口 |

只有一个小组／培训等工作区时，提供直接入口；多个工作区时使用可展开菜单。发布不按前端角色名称猜测，SYSTEM_ADMIN也不会因为管理身份自动得到发布入口。

没有新增置顶、重要程度、推荐或紧急等级。列表采用实际类别、版本、范围、摘要、发布时间、截止日和查收状态；列表缺少发布人字段时不虚构名字，详情仍显示真实作者。没有改变排序、分页、搜索匹配、接收层级、范围、验码、签字、收藏、导出、审计或数据结构。

## 问题、方案与实现

| 原有具体问题 | 对应处理 |
| --- | --- |
| 所有个人与管理按钮权重相同，手机显示半截入口 | 固定轻量个人标签；管理按原权限进入工作区；选中状态同时使用颜色、下划线和辅助技术语义 |
| 发布按钮单独占一行，顶部操作堆叠 | 标题、数量状态、发布与工作区整合，不增加欢迎大卡片 |
| 分类横向排列难以完整识别 | 默认显示当前分类，展开全部七个选项（含全部），手机两列，不裁切 |
| 搜索后语境、清除与异常处理不足 | 结果数、明确清除、保留控件和原条件重试；旧查询不能覆盖新栏目 |
| 卡片元数据与动作缺少层级 | 类别与状态在上，标题摘要在中，范围版本在后；日期和动作在下，桌面收在右侧 |
| 所有空栏目只显示“暂无公告” | 分栏目提示与下一步；不制造业务数据填空，也不对无权限用户显示发布按钮 |
| 加载和失败只有一行文字 | 静态骨架、同范围重试、明确错误、成功提示和操作锁 |
| 阅读与长表单节奏不统一 | 正文阅读宽度、发布范围／内容／接收／日期分段；验码后将签名区带入视野 |

沿用海军蓝、品牌蓝、系统字体、公共顶栏和底部导航；公告样式单独封装。桌面公告页避免重复视觉主标题，其他页面不受影响。手机主要操作不小于44px，输入16px起，沿用原安全区及底部预留。

标题21–23px、公告标题15–18px、摘要13px、正文16px。长标题完整换行，摘要最多三行，详情保留全文。辅助文字加深对比度。图标复用既有`navIcon`线性语言。

主要反馈150–180ms，无循环装饰；遵守减少动态效果。栏目支持键盘左右／首尾，菜单支持Escape和点击外部关闭。收藏请求锁定，成功后更新，失败不保留假成功；验码及签字继续由原接口校验。后台计数刷新同步标签、底栏及顶部说明，`99+`只用于紧凑显示，精确数量仍保留。

没有引入UI框架、字体包或插画资源。新增CSS与展示模块约24.9KB，gzip合计约6.9KB；这是文件测量，不等于服务器传输或首屏耗时实测。
