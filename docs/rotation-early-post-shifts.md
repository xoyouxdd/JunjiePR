# 7点岗位允许跨班次预排（仅本地）

小C、迎宾、快迎1等带有seven标记的岗位，可以在可编辑预排中安排其他班次的本日轮岗人员。人员交换、从人员区安排及原有下拉选择均适用，不增加入口。

- 预排岗位显示“7点岗位”标记；涉及这些岗位的交换确认框提示“为7点岗位，可安排其他班次人员；按实际班次生效，不提前计时”。改名和岗位整体交换保留标记。
- 岗位标记与人员班次分开处理。非07:00人员记为普通预排人员，保留原班次，到其班次才开始实际在岗计时，不作为推7点对象。
- 推7点安排继续按实际07:00预排人员及原顺序处理；已被安排到岗位的接替人员移出推7点名单，不保留超出实际需求的职责，也不误删仍适用的接替人员。
- 沿用实际轮岗规则、班次、餐休和角色权限。首班后、历史班表仍只读；OP、不轮岗人员、重复人员/岗位、陈旧版本及事务保护继续生效。
- 原下拉设置切换岗位人员时同时清理该岗位的旧安排，避免同一岗位同时出现在seven和crew两份安排中。

验证：每日班表34项；正式轮岗39项；事务边界80项；引擎与workflow合计74项。新增真实引擎发布测试覆盖三种7点岗位名称、07:15/09:00班次、不提前计时、不误标7点人员、下拉与人员区替换、其余推7点人员保留。

rotation_early_post_ui.cjs在Edge/WebKit检查真实隔离接口、交换提醒、跨班次保存、下拉当前值及候选人、改名标记保留与320/390/1024宽度；rotation_daily_ui.cjs在Edge/WebKit回归每日预排、交换、版本冲突、历史只读、首班固定和权限。JS语法、diff检查通过。新浏览器测试已登记到run_all.py。

## 再次复查（2026-11-03）

发现并修复一处配对遗漏：用其他班次人员替换第一个或中间的7点人员后，仅截短推7点名单会把后续接替人员顺次绑定到错误对象。现在在这类预排调整中保存仍有效的接替对象关系，其他人员不顺次前移；旧班表没有这类关系时继续使用原来的配对方式，不迁移或改写历史。

原有推7点设置直接标明“接替谁”。恢复的07:00人员尚未分配接替者时保持空位，不挪用其他岗位的接替者；在原设置中补选即可。保存携带对应对象，前序空位不会压缩后续关系，过期或不匹配的对象列表拒绝保存。明确重新选择普通名单的旧调用方式仍兼容。系统补选接替人员时继承其原目标，不改变其他接替关系。

本轮后端验证：每日班表43项、正式轮岗39项、轮岗引擎32项和workflow43项，共157项通过。新增测试覆盖三处岗位分别通过人员区、下拉和岗位间交换替换，保留其余配对；还覆盖按实际班次计时、恢复原7点人员、空位保存、陈旧对象拒绝且回滚、手动重新配置及自动补选。

本轮浏览器验证：跨页面一致性测试在Edge/WebKit/Firefox通过，新增检查有空位时设置显示值与实际接替对象一致；7点岗位真实接口UI及每日班表回归在Edge/WebKit通过，包含首班固定、历史只读、权限和窄屏布局。先前未变化的其他事务回归结果复用，未声称本轮重跑全量发布验证。JS语法与diff检查通过。
