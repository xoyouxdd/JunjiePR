# 分值设置：分类规则与版本

本地实现，未上线。沿用原“分值设置”入口，无新增业务导航。

## 初始规则与权限

没有显式配置时继续使用现有规则，启动不改写角色、历史分值、认可类型或处分等级：

- MSP固定3分、不限月次数；表扬信固定3分、每月一次，重复拦截。
- 安全、礼仪、包容、效率、演出从2026-09-01起各类别每人每月封顶5分。
- 小伙伴按原签发人角色计分；正式主管保留GSM签发0.5分、AM签发1分等原有差异；代理资格、本职归类、签发人及复核权限不变。
- 处分等级默认声明1分、备忘录3分、一级警告5分、二级警告10分。普通扣分逐条累计；考勤与违规病假仅按3个月范围内两张未用于升级的有效声明配对，来源不重复计分。备忘录、警告及升级结果不参与后续自动升级。
- 设置页仍只有原SYSTEM_ADMIN角色可写；HR_CIRCLE和HR_ADMIN只读，其他角色不新增配置权限。此处不沿用“关于系统”名单的ADMIN专属账号规则。
- 类别配置只能在原能力内缩小登记范围。主管仍不能登记迟到/早退30分钟以上，仍限声明等级；固定扣分类别仅经理登记。重复判定的跨类别分组沿用原规则，界面只读，不允许修改升级边界。

## 页面与保存

“小伙伴加分”“主管加分”“减分设置”三个页签。每个人群独立设置类别及认可人角色分值。

- 加分类别支持按角色/固定分值、每月最多计分N次、类别月度上限，可同时启用。次数超限可选择“登记但计0分”或“拒绝登记”。部分剩余额度仅计剩余分值。
- 减分类别支持按等级/固定扣分、逐条累计/重复升级。固定扣分与处分升级不能混用，避免升级来源重复计分。
- POC保留专用入口，不在普通类别中更改规则。类别删除按停用处理，保留历史、类型主键与规则版本。
- 日期对应版本，预览确认后写入；角色分值、等级分值批量修改为同一事务。所有写操作检查配置修订摘要并记日志，旧页面提交冲突返回409。
- 新增自定义减分类别由规则表标记，启动参考数据维护不会误停用。

## 实际计分

- 新的scoring_policies表保存kind/scope/code/生效日期的版本；旧角色分值表继续作为无新配置时的默认来源。
- recognition_records与deduction_records新增可空规则快照字段。启动迁移只补列，已有记录保持NULL及原数值。
- 新认可提交时冻结分值和类别规则，确认时按冻结规则计算实际计入分值。待复核期间管理员变更配置不会改变该记录的规则。计分按员工×类别×认可月份累计，跨月重置。
- 拒绝模式在写锁内检查pending/confirmed预占次数，复核还原同样检查；0分模式在确认写事务内限制计分次数。幂等提交、整批事务、月结和原自认禁令保留。
- 普通扣分、违规病假联动、补材料、声明升级结果和处分级别纠正使用同一规则来源或记录快照；历史记录不因设置变更重算。
- 登记页面按所选业务日期刷新类别与分值，不用今天的选项代替历史日期。后台仍独立校验，绕过前端无法扩大权限。

## 验证入口

- test_scoring_config.py：默认一致性、各角色鉴权、固定分、次数/封顶组合、并发、跨月、生效日期、待复核快照、迁移、重启与审计回滚。
- scoring_config_ui.cjs：真实API与真实页面，手机/桌面布局、保存、独立人群及HR只读；只连接临时数据库。
- 原批量认可、主管绩效、声明升级、扣分材料、分值审计和完整前端模块回归。

## 入口复查补充

- 补材料接收及后台转换完成前均按记录冻结的重复规则校验；如期间出现同类处分，级别不足的记录保持不计分并提示按原升级流程处理，不自动加重处分。旧草稿使用原有重复类别规则，不套用后加的配置。协助上传者不改变原计分快照。
- 旧记录没有配置快照时，处分级别纠正及升级结果继续使用原等级分值，不能读入后来追溯生效的类别固定分值。
- 对2026-09-01之前新登记且显式配置的规则，明细、SQL汇总、个人看板、排名、月结及兼容视图统一使用实际计入分值；真正的旧记录仍按原历史口径。旧迁移重复执行也不覆盖配置记录的零分结果。

- 计分规则解析拒绝紧凑日期及周日期，防止利用字符串比较和月份截取绕过生效日、次数和月度封顶。
- 直接上传PDF且立即计分的扣分，同样在flush取得写锁后复查重复升级及确认状态；并发提交不能重复按较低等级生效。
