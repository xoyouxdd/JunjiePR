# 常用 UI 统一走查与优化（2026-10-20）

本地候选版本 `2026.10.20.3`。沿用当天公告中心确定的专业、克制、清晰、轻反馈风格：海军蓝与品牌蓝、柔和中性色、轻边界、明确的主次操作。游戏化的仪式感继续留在荣誉展示，不扩散到登记、复核与人员管理。

本轮只修改本地前端、版本说明与相关验证，没有推送、打生产包、部署或修改线上数据。所有演示使用独立测试环境与虚构人员、36条模拟认可；普通本地服务与正式数据库未用于本次 UI 数据生成。

## 走查范围

通过本地真实 FastAPI 接口登录隔离账号，打开实际 HTML、CSS 和原生 ES 模块，未用静态设计图代替系统页面。权限来自真实账号和接口；没有通过给所有账号赋管理员权限生成截图。

覆盖11种角色：CM、TR、TA主管、主管、TA GSM、GSM、AM、OM、景点圈HR、HR管理员、最高管理员。其中代理身份沿用原基础职务与权限。

覆盖23类菜单页面：

- 首页与我的签卡、待办、公告、认可/绩效登记、组员复核、主管复核。
- 组员记录、登记记录、景点统计、PR排名、声明统计、月报制作。
- 员工管理、小组管理、月结、跨圈调动、LOA、缺勤登记、景点圈HR账号。
- 审计日志、分值设置、系统运营、账号页面的布局。

轮岗测试有独立应用与设计体系，不在本轮批量重绘范围；荣誉与勋章的专属素材和动画保持原样。账号页面仅检查布局，账号规则没有调整。

## 原问题与实际处理

| 问题 | 本轮处理 | 对业务的影响 |
| --- | --- | --- |
| 按钮、表单、卡片与列表细节分散，页面之间完成度不一致 | 公共工作区样式统一文字层级、边界、间距、焦点、次要按钮与触达尺寸；公告和轮岗继续独立作用域 | 不改变控件提交字段、权限或动作 |
| 手机筛选竖排较长，数据在首屏下方较远 | 适合配对的筛选使用两列，主次操作并排；窄屏控件保留16px文字，不靠缩字塞内容 | 查询条件及查询接口保持不变 |
| 统计表固定组织列过宽，小屏难以看到数值 | 固定列180px，组织元数据换行，完整数据表仍在表内横向查看 | 全部6列和原排序、展开层级、计算口径保留 |
| 桌面页面标题在外层与内容区重复 | 内容标题承担主标题；侧栏继续明确当前页面 | 不调整导航成员及入口权限 |
| 待办与数据视图导航像一组同权重操作按钮 | 轻量下划线选中态，数值徽标保留；主操作继续品牌蓝 | 栏目及计数含义保持不变 |
| 手机日期与认可类型并排，iOS本地化日期可能挤压相邻字段 | 手机上日期、认可类型各占一行，保留原生日期输入及提交回退 | 日期解析、补录、月结与当日角色规则不变 |
| 原生optgroup只能显示标题，不能折叠组内人员 | 可视签卡人菜单使用原生details：分组默认关闭，可展开/收起，选择后关闭；原生select仍负责值、必填与提交 | 本人排除、人员范围、分值、特殊认可及每条独立选择保持不变 |
| 长人员列表可能接近固定提交栏 | 菜单高度适应可视区，展开时将控件带入视野；30人分组可选择最后一人 | 不删除或限制候选人员 |
| 月报选填资料占用较多纵向空间 | 活动照片、工作说明、生日祝福、活动说明集中到可折叠补充区；桌面主筛选三列对齐 | 原字段仍在DOM中，折叠不清空内容，不改变导出读取 |
| HR工具上的“展开”小标签在窄屏被挤成两行 | 标签不收缩、不拆字 | 仅排版变化 |
| 普通复核说明全部呈红色，容易和风险提示混淆 | 常规说明使用辅助文字色；状态标签及拒绝按钮继续保留语义色 | 原状态和说明全文保留 |
| 手机提示可能遮住固定提交按钮 | 工作区存在固定提交栏时，提示上移避让 | 不改变成功/失败判定和提交锁 |
| 复核页跨断点重新加载后快速切页产生未捕获的取消请求 | 布局、历史和分页重载统一处理取消；真实错误仍提示，旧页面不得覆盖新页面 | 不改变复核队列、分页或处理行为 |

## 建议的下一轮优先级

| 优先级 | 建议 | 为什么 |
| --- | --- | --- |
| P1 | 在真实iPhone Safari、微信、主屏Web App和一台安卓上走完相册选图、日期、分组选择、键盘与提交 | 浏览器视口检查无法证明iOS原生控件、键盘和相册上传的真实兼容性；此前上传问题必须独立验收，不能用UI通过代替 |
| P1 | 员工管理下一轮以“找人、改人”为主，导入、新建、工号变更集中到工具区 | 当前三个低频工具仍在组织列表前，手机首屏离人员查询较远；这是值得做的结构级优化，本轮只统一它们的排版，没有隐藏或搬走已有功能 |
| P2 | 给手机统计页补充同一字段的摘要浏览方式，完整表格保留切换 | 固定列缩窄已改善可见性，但多列精确对照依然需要表内横向查看；摘要应该复用原值，不能增加分数、评价或计算口径 |
| P2 | 复杂表单继续统一“当前任务、必要提示、完整规则说明”的阅读层级 | 减少初次打开的说明密度，同时确保完整规则可随时展开，不删除提醒 |
| P3 | 将已稳定的筛选、标签导航、记录卡片和状态组件逐步归并 | 现有公共样式与局部样式仍有历史叠加；分批收敛可降低后续页面发生风格漂移和特例覆盖的风险，不宜一次重构全站 |

建议下一轮先完成人员管理的信息架构与真实手机验收，再考虑统计摘要视图；不用继续给普通工作页面堆装饰和动效。

## 文件与边界

当前候选补充修改涉及：`workspace-ui.css`、`registration.js`、`reviews.js`、`monthly-report.js`、`hr.js`、`submission.js`、`version.py`、`changelog.py`、`frontend_modules.cjs`、`test_changelog.py`及相关文档。工作区作用域沿用既有导航设置，不新增导航权限分支。

本机实际使用Chromium/Edge。没有可用的真实Safari/WebKit或物理手机会话，因此尚未认证iOS、微信WebView、软键盘和主屏模式；本轮也未逐页重新渲染全部PPT/PDF导出文件。95分是设计目标，本报告不自报达到。


## 补充逻辑复查

本轮继续复查发现并修正：

1. 月结改变月份或景点圈后，立即清除原结果和关闭/重开按钮；旧查询、旧明细与过期确认不会操作旧范围。重新查询先显示加载状态，失败可重试；月结操作增加页面级重复操作锁，后端月份、权限、检查清单和审计规则保持原实现。
2. 月报章节、候选人和补充材料接入既有离页保护。取消离开保留文字、勾选和照片，只在当前页面内存保留，不写入浏览器存储。
3. 月报导出期间重新预览不能放开导出锁；失败后保留文字和照片，可重试。导出使用点击时的月份、范围、模板与预览摘要，不在请求进行中替换已发出的配置。

`frontend_modules.cjs`新增延迟旧月份返回、过期确认不写入、取消离页、照片保留、导出失败和重新预览期间重复导出等实际DOM回归。全部使用合成资料，无生产写操作。
