# 声明登记统计

最高管理员可在现有明细的处分等级字段直接选择声明、备忘录、一级警告或二级警告，填写原因后确认更正；没有新增菜单或独立页面。仅更正独立、可处理记录的等级及对应扣分，保留原登记信息、材料与业务状态，记录前后值及原因并刷新统计缓存。提交校验原等级，旧页面冲突须刷新。已月结、作废、处理中及升级工单关联记录保留原保护，不通过此操作绕过原审核流程；其他账号仍只读。

「声明登记统计」按月查询声明扣分记录，可选择景点圈、处分等级、处分类型、业务状态，并按员工姓名或工号搜索。页面显示总记录数、涉及人数、各景点圈及等级汇总和逐条明细；明细含原景点圈、登记人、材料与升级状态。已批准升级的第二条原声明与升级结果不重复计数。

页面默认「全部状态」包含已生效、审核中、待补材料（含材料处理中、失败），通过显式 `status=current` 同步传给查询和 Excel 导出；可单独查看已作废，或选择含作废的全部状态。未传状态的旧接口调用及 HR 月报保持原口径。员工搜索支持部分姓名、工号匹配，候选取自当前月份和筛选范围的登记快照，不受当前在职、调圈状态影响；可选择候选，也可直接用关键词查询。

查询与展示状态映射由 `backend/app/services/declaration_statistics.py` 负责；路由保留参数、权限、Excel、审计和响应，HR 月报直接复用查询服务。接口字段和查询口径保持相同。

已批准升级时，第二条原声明仍保留在业务记录中并标为「升级来源（不计分）」；第一条原声明和升级结果按实际分值计入月度分数。统计、PR 排名及导出使用相同的实际扣分口径，不把第二条原声明再次计分。

升级审批与转交在取得数据库写锁后重新检查待处理状态和当前审核人，并原子领取工单。并发审批、拒绝或转交仅允许一个当前操作生效；结果处分、材料记录及审计同一事务提交，失败全部回滚，不重复生成有效处分。

审核不通过后，旧工单、第二条作废声明、材料和审计继续留档；第一条声明释放占用，可以与另一张新声明重新配对。数据库仅对未被拒绝的工单保留第一条声明的唯一占用，待材料、待审核和已批准工单仍不能重复占用。旧库通过可回滚迁移调整约束，不删除历史工单或转交记录。关联卡片按工单号和审核状态同时展示被拒历史与当前配对关系，历史第二条声明不会恢复计分。

## 权限与范围

`DECLARATION_STATS_VIEW` 允许查看所有景点圈及可用的声明材料；`DECLARATION_STATS_EXPORT` 还允许导出。TA主管、主管、TA GSM、GSM、AM、OM、HR管理员、景点圈HR和系统管理员均同时具备这两项权限，因此**主管可以跨圈查看和导出**。该统计是跨圈只读入口，不改变原登记、审核或HR管理范围。

| 操作 | 接口 | 要求 |
|---|---|---|
| 查询 | `GET /api/declaration-statistics` | `DECLARATION_STATS_VIEW` |
| 导出 | `GET /api/declaration-statistics/export` | `DECLARATION_STATS_VIEW` 与 `DECLARATION_STATS_EXPORT` |
| 查看材料 | 明细给出的 `/api/files/{id}?preview=true` | 已登录且具备声明统计查看权限；文件仍须为有效材料 |
| 下载材料 | 明细给出的 `/api/files/{id}` | 与查看材料相同的权限，不额外要求统计 Excel 导出权限 |

桌面表格与手机明细均保留「查看材料」并提供「下载材料」。声明材料下载名为 `事件日期_员工姓名_声明类型.pdf`，例如 `2026-09-24_凌元富_考勤-未打卡.pdf`；使用登记时的人员和类型快照，文件名中的路径分隔符等非法字符替换为短横线。仅改变下载名称，不重命名服务器原文件。下载仍带当前账号水印并记录审计；未就绪或无有效材料的记录不提供下载入口。

查询和导出使用相同筛选口径。导出工作簿含「景点圈与等级汇总」和「逐条明细」，加当前导出人工号水印并记录导出审计。导出表只提示材料是否可在系统内查看，不附带材料文件本身。
