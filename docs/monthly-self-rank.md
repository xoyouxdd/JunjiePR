# 我的信息：月结段位与组员历史

CM/TR、代理TA主管和本职主管在本人首页 / 我的成绩的「我的信息」查看月结段位。整个信息板块使用确认后的立体金属徽章、随计分月份切换的春夏秋冬背景，以及段位对应的名称和总分颜色；评语独立显示在段位区间下方，手机分数为四列两行。待月结、等待全圈汇总和重新核算时显示浅色锁定提示，不显示已获段位；其他无有效结果状态单独说明。

视觉资源位于`backend/app/static/images/ranks/`：`rank-emblems-v2.png`为十档透明徽章图集，`rank-seasons-v2.png`为四季背景图集。首页通过CSS定位图集，沿用真实月份、段位状态和已封存评语，不以图片决定排名或权限。

## 比较口径

- CM/TR与代理TA主管（TALEAD）按月结时的景点圈和封存本职身份归入一线组。
- 本职主管与代理TA GSM从2026年10月起合并全部景点圈比较。参与主管计分的各圈全部月结后，使用各圈有效封存分数统一生成段位；只有本人圈已结时仍等待汇总。全局关闭也可完成统一封存。
- 综合分复用实际计入加分＋全勤分－有效扣分，五类认可月度上限、POC独立计分和LOA排除规则保持不变。
- 分母为同组人数减本人；分子只计算分数严格低于本人的人数。同分不算超过，同分员工获得相同档位，不以工号决定高低。
- 月结前补齐本圈有计分资格人员的缺失全勤行。真实零分人员参与，LOA整月排除。仅一人时显示「暂无可比较数据」。
- 只展示达到的最高「超过」档位，不显示精确百分比、名次或超过人数。刚好90%为超过80%，刚好10%为黑铁。

## 封存与重开

关闭月结时，在原关闭事务中补齐计分人口、生成组织与段位快照；任一步失败整体回滚。快照保留分数组成、分类加分、人数与严格低分人数。后续调圈、身份变化或人员停用不重新计算已关闭月份分数。

再次关闭替换该关闭范围的快照代次。全局月结与单圈月结各有代次，遵循现有全局关闭优先规则；全局重开时仍关闭的单圈继续使用其有效代次。主管快照保存各参与圈有效关闭ID与时间的联合签名，任一参与圈重开都隐藏全部主管段位，待重新全部月结后更新统一结果；其他圈仍关闭的一线段位保留。

只通过现有月份下拉框查询，不增加快捷入口或查询按钮。下拉框按年份分组，提供最近三个月及本人有计分记录或组织快照的历史月份，标注“已月结”“待月结”或“重新核算中”。

分数、段位和比较范围始终对应所选月份。历史组织快照存在时，展示月结角色、景点圈和小组；无快照时明确标为当前信息。重开、LOA和人数不足单独提示。

切换月份立即清空旧结果并显示查询状态；失败时提供“重试”。快速连续切换时，只接受最后一次查询结果。既有已关闭月份按现存组织快照和计分证据补建，先处理较早月份，确保首次生成评语可以取到上月封存分数；不修改源分数，缺少完整依据时不展示段位。

## 签卡汇总与组员查看

“我的签卡”标题下、列表上方显示已计分、待复核、已确认未计分和不通过张数；零张的后三项隐藏，随所选月份更新。已计分仅包含有效确认且实际计入分值大于0的签卡；LOA和达到上限的零计分签卡进入“已确认未计分”。不新增总分算式。

一线CM/TR及代理TA主管暂不显示“绩效分怎么算的 / 本月总分怎么算的”入口或说明正文，当前月和历史月均适用。按登录者当前本职身份判断，不因历史月份角色变化而开放；正式主管和代理TA GSM保留现有说明，计分规则不变。

现任正式组长与代理组长通过既有“组员记录”月份筛选查看当前负责成员的有效历史段位，成员撤出后不能继续查看。显示段位名与超过区间，不提供具体名次、精确百分比、比较人数或成员个人评语。关闭失效时不返回段位。有原记录权限的负责人保留原成绩明细；其他现任负责人只返回成员身份和段位，不扩展记录或具体分数权限。

## 数据与权限

- 实现：`services/monthly_ranks.py`；关闭事务入口 `routers/governance.py`。
- 表：`month_rank_generations`、`employee_month_rank_snapshots`；已有段位快照表通过幂等迁移补齐`comment_text`和`comparison_scope_json`，保留原行。
- `GET /api/dashboard?month=YYYY-MM`的`month_rank`只取当前登录员工；`recognition_summary`返回本人所选月份签卡汇总。段位对象返回状态、段位、文案、月份和比较范围，不返回精确比例、人数或其他人的排名。
- `GET /api/member-score-summary?month=YYYY-MM`以实时直属/可监督成员范围过滤。无原记录权限但有现任组长分配时返回`rank_only=true`与只含身份、段位的行。
- 原签卡、审核和撤回权限保持原流程。

## 验证
