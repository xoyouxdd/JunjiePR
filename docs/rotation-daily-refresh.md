# 每日班表交换刷新修复（仅本地）

## 行为

- 同日读取和交换保存期间保留原班表 DOM，不用月历替换整个下方内容。
- 保存中停用编辑与拖拽，原操作提示显示保存状态，避免重复提交。
- 成功后读取当天的权威结果再一次更新；沿用后台交换与版本校验，不在浏览器提前交换数据。
- 交换后的前台流程为一次保存和一次当天读取；不重复读取整月，不等待另一次实时看板读取。既有 SSE、轮询和首班冻结检查保持工作。
- 保留页面和外层滚动容器位置、原列表滚动及折叠状态。提示更新也保护浏览器滚动锚点。
- 提示行使用外部样式表保持单行，兼容页面CSP；刷新测试时钟前保存滚动位置，避免时钟重绘后才捕获已经偏移的位置。刷新失败、重试及保存成功均验证逐帧滚动稳定。
- 保存失败或冲突时仅重读当天；重读失败保留旧画面并禁止继续编辑，提示刷新后重试。
- 迟到响应受日期及请求序号保护，不覆盖用户后来选择的日期。权限失效时仍沿用原有拒绝与清屏处理。

## 验证

- `rotation_daily_refresh_ui.cjs`：真实页面和临时服务，390/1440 视口；逐帧检查班表是否存在及滚动是否偏移；验证人员/岗位交换、请求数量、重复提交拦截、保存失败、版本冲突、重读失败及恢复、保存期间切换日期。
- `rotation_daily_ui.cjs`：原有每日班表流程、触屏拖拽、重命名、历史只读、今日首班前同步及首班冻结、六种宽度、成员/大屏权限。保留 DOM 后，拖拽测试显式等待加载和弹窗完成。
- `rotation_formal_ui.cjs`：正式轮岗角色页面及五种宽度。
- `test_rotation_daily.py` 18 项、`test_rotation_formal.py` 38 项通过；后台交换、鉴权及事务代码未修改。

测试使用独立临时数据库及本机临时端口，不操作正式数据，不推送或部署。

浏览器结果：Edge、WebKit 均通过新增交换刷新检查和正式轮岗页面检查；原每日班表完整浏览器回归在 Edge 通过。合并请求计数只统计交换前台流程，既有 SSE/轮询后台请求仍独立运行。
