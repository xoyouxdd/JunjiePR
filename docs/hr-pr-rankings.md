# 景点圈HR的PR排名数据

发放榜按签卡人统计有效已确认认可，每条计一次，代录人不计签卡贡献。主管及GSM榜增加按签卡发生景点归类的次数列，合计等于总数；GSM等管理视角按签卡人所属圈筛选，景点圈HR仍仅统计本圈CM/TR收到的认可。排除本人认可本人、系统固定分值与临时认可资格。页面与Excel使用同一服务计算。

热力追踪、矮人迷宫、小熊罐子的景点圈HR账号（`HR_CIRCLE`）开放「PR排名数据」菜单和Excel导出。个人绩效仅开放本圈CM/TR的综合分、加分、扣分和缺勤；主管个人绩效人群不开放。主管发放排行及GSM/TA GSM认可次数榜继续保留，按用户确认显示次数和累计发放分值，属于本圈发放贡献统计，不是主管本人的绩效分。允许榜单的日期、类别、搜索、排序及分页口径与GSM选择该圈时一致。页面仅显示本圈，排名人群仅有CM/TR。该限制仅针对PR排名，「景点数据与导出」按用户确认保持原权限。

查询和导出共用服务端范围校验：省略景点圈参数时自动使用所属景点圈，指定其他圈或主管个人绩效人群均返回403。没有所属圈、所属圈停用或不再属于员工景点圈时拒绝访问。每次查询先校验权限再读取缓存，缓存按账号、角色、有效景点圈及筛选条件隔离，不通过缓存绕过范围变化；旧主管个人绩效缓存亦不得返回。

后台导出任务在入队、执行及下载时复核相同景点圈、人群和榜单范围；任务执行仍调用原PR排名导出接口。账号调圈、权限变化或访问此前的主管个人绩效任务时，旧导出文件不能继续下载；本圈主管发放统计任务保持可用。Excel内容、表结构、身份水印、导出审计保持，审计额外记录实际景点圈及排名人群。

不赋予HR账号GSM角色，不新增全局数据权限。原GSM/AM/OM查询与导出范围、TA GSM仅查询的规则保持；HR管理员、最高管理员及其他角色不因本次调整获得额外PR排名权限。其他模块的权限不变。

定向验证：`tests/test_hr_pr_rankings.py` 使用隔离数据，对比三个HR账号与GSM在相同景点圈的查询及Excel数据，覆盖跨圈请求、后台导出、缓存及下载范围重校验；`tests/hr_pr_rankings_ui.cjs` 覆盖菜单、固定景点圈、筛选及导出操作。
