# 缺勤导入工号及姓名匹配（本地）

- 员工号作为唯一定位依据：共享规范化规则兼容7位原工号与增加一个前导0的8位写法，保留7位工号本来的前导0。Excel数字单元格丢失前导0的原解析兼容继续保留。不再无条件删除任意首位。
- 同时查询规范工号及别名；对应多个档案时阻止整月覆盖，不能通过确认跳过绕过。
- 姓名只辅助验证，不用姓名寻找其他人员。规范化大小写、空格及分隔符后，系统姓名须包含文件中的有效完整姓名部分。单个汉字、英文首字母、空值不自动通过；英文按完整单词匹配，Ann不会误匹配Joanne。不猜测中文名与英文名的翻译关系。
- 沿用员工事务报表的“英文, 中文”姓名字段格式，同时兼容中文逗号。预检显示文件工号/姓名、系统工号/姓名及匹配依据。
- 提交在写锁内重新检查人员身份、别名歧义、有效姓名、在职和圈权限；失败时不覆盖旧缺勤。实际记录继续保存系统工号和系统姓名快照。
- 角色权限、月份及总数对账、LOA保护、月结和旧记录“已覆盖”处理不变。未匹配仍须人工复核，不能只凭同名自动挂接。

验证：缺勤导入64项、单人备用登记26项、已覆盖记录披露2项相关测试通过。新增预检对照UI在Edge及WebKit的390/1280视口通过，包含转义及权限检查。测试使用临时数据；未推送、未部署。
