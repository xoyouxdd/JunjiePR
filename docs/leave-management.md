# LOA 与月度病假事务导入

本页说明 LOA、月度文件导入与单人备用病假登记。LOA 是长期病假期间，按整月排除计分；月度病假事务导入是 HR 的 `.xls` 文件明细，不等同于 LOA。单人备用入口位于「缺勤登记」，无需病假证明。旧人工病假登记接口保留历史兼容，但当前生产角色均不具备 `SICK_REGISTER` 权限，主管导航也不再显示该入口。

## 权限与范围

| 功能 | 权限 | 当前角色 |
|---|---|---|
| LOA 登记、补结束日期、撤销 | `LOA_REGISTER` | TA GSM、GSM、AM、OM、景点圈 HR |
| 月度病假事务预检、提交、未匹配文件下载 | `SICK_LEAVE_IMPORT` | GSM、景点圈 HR、系统管理员 |
| 单人备用病假搜索与提交 | `SICK_LEAVE_IMPORT` | GSM、景点圈 HR、系统管理员；允许跨景点圈、全部员工角色 |

LOA 员工搜索允许上述有登记权限的账号查找全部在职员工，不受其日常 HR 管理景点圈范围限制。月度文件覆盖按导入账号的权限范围执行：景点圈 HR 只覆盖本圈员工，全局导入角色覆盖全部景点圈。文件中的员工若工号不存在、姓名不符、已离职或不在当前账号可导入范围，预检会逐行列明原因并跳过；登记人复核后可继续提交。景点圈 HR 文件中的圈外行会跳过，圈外员工的系统记录不受影响。`GET /api/accounts/reset-targets` 仅服务于有 `PASSWORD_RESET` 权限的账号选择重置对象，原角色与目标范围规则不变。

## LOA 规则

- 入口为「LOA登记」。先按姓名或员工号选择员工，再登记进入日期；可在以后补填结束日期。历史记录可填写原因后撤销。对应接口是 `GET /api/loa-periods`、`POST /api/loa-periods` 和 `DELETE /api/loa-periods/{id}`。
- LOA 与自然月只要有一天交集，该员工整月的全勤、认可和扣分记录保留，但不参加当月综合分及小组汇总。统计页在 `loa_rows` 中另列人员，Excel 导出新增「LOA明细」。
- 起止日期不能反向、不能与已有 LOA 重叠。每次登记、补结束日期或撤销，只对排除状态实际发生变化的月份做月结检查和全勤重算，并写审计记录。因此开始月已月结时仍可补结束日期，但若结束日期使某个已月结月份恢复计分则拒绝；撤销会影响该 LOA 覆盖的全部月份，其中任一已月结则拒绝。未填结束日期的 LOA，覆盖范围计到当前月（及该员工已存在考勤记录的最晚月份）。

## 月度病假事务导入

1. 在「缺勤登记」先选择覆盖月份，再上传该月完整的 HR Excel 97–2003 `.xls` 事务文件（不超过 10 MB）。`POST /api/sick-leave-imports/preview` 同时接收表单字段 `month=YYYY-MM` 与 `workbook`，核对事务区和总数区（区块标记「事务:」「总数:」，全角冒号亦可）、文件所有事务日期是否属于所选月份、源 ID 去掉首位后的 7 位员工号、姓名、在职状态、权限范围及 LOA 日期。源 ID 为 8 位数字；丢失前导 0 的 ID（数字或文本，如 `1727264`）会左补 0 到 8 位再核对姓名；超过 8 位或含非数字字符的病假行记为阻断错误。事务区与总数区按归一化后的同一源 ID 对账，病假时数须为大于 0 的 4 小时倍数。即使当月没有病假行，也须由其他事务日期证明文件月份，不能凭空文件清除旧记录。
2. 预检会列出文件匹配、未匹配、LOA 保护明细，以及本月将覆盖的旧记录数和**没有可匹配文件缺勤的旧缺勤员工数**（既可能未列在文件中，也可能在文件中但匹配失败）。员工匹配失败不会阻止提交，但必须由登记人逐行复核原因；这些行不写入缺勤，可通过 `GET /api/sick-leave-imports/{token}/unmatched-file` 下载标红文件。文件结构、事务与总数对账或月份不符仍会阻止提交。预检通过后，即使没有匹配的病假行，也可将所选月份的旧缺勤清零。
3. 确认后调用 `POST /api/sick-leave-imports/commit`，请求体同时提交预检令牌和相同的 `month`；有未匹配员工时还必须提交 `reviewed_unmatched=true`，由后端核验。在账号权限范围内，所选月份的全部旧有效病假（人工登记、违规病假及旧月度文件导入）统一标记为 `covered`，包括文件未列出或文件中匹配失败的员工；再写入文件中匹配的病假明细，并为受影响员工重算全勤。旧记录保留历史，但不再参与病假计天。审计保留登记人、跳过行号、员工号及原因。LOA 不会被覆盖；已月结范围不可覆盖。提交前重新核对 LOA，若预检后出现日期冲突则返回 409，必须重新上传预检。

预检会从 `.xls` 工作簿中定位唯一一张具有「事务」和「总数」区块的报表工作表，不要求它是第一张；区块后的表头允许空行、空白及列顺序变化。多个完整报表、重复/缺失表头、月份不符或对账不一致均拒绝提交，错误提示工作表与行号。标红的未匹配文件保留原工作表顺序，只标记实际报表工作表中的对应行。

`GET /api/sick-leave-imports/records?month=YYYY-MM` 单独列出所选月份的月度文件及单人备用病假，并显示来源、景点圈快照、登记人及覆盖状态；「我的登记记录」保留旧人工登记历史，不混入新的月度文件或单人备用记录。景点圈 HR 继续查看本圈文件记录，同时可查看自己跨圈提交的备用记录。

## 单人病假登记（备用）

- 在「缺勤登记」切换到「单人病假登记（备用）」。复用绩效登记的员工搜索交互，通过 `GET /api/sick-leave-imports/employee-targets` 按姓名或工号模糊查询全部在职员工，默认全部景点圈，不限制员工角色或是否拥有登录账号。必须点选员工，空关键词不返回名册；搜索支持景点圈筛选。前后端校验 `SICK_LEAVE_IMPORT` 入口权限，有该权限的账号可跨圈提交。月度文件覆盖的原范围保持不变。
- `POST /api/sick-leave-imports/single` 接收 `employee_id`、`leave_start_date`、`leave_end_date`、`leave_days`、`leave_type`、可选 `note`、`rest_day_confirmed` 与 `idempotency_key` 表单字段；无需 `proof`。病假类型为法定病假、全薪病假或无薪病假；实际天数按 0.5 天递增，不能超过日期跨度，起止日期须在同一自然月，多日登记须确认不含本休。
- 后端检查在职员工、已有有效病假的日期交集、LOA 日期交集与目标景点圈月结。提交前取得 SQLite 写锁，再检查日期交集及幂等键，防止重复计天。幂等键复用原提交机制，改用不同内容会被拒绝。登记成功写入现有 `sick_leave_records`，`import_source=single_backup`，保存员工/角色/景点圈快照、登记人、时间、备注及审计。
- 复用 `recalculate_attendance` 现有全勤规则；非计分角色保留缺勤记录，不新增全勤资格或扣分规则。该入口不生成违规病假处分。
- 后续整月文件覆盖包含此来源；在文件导入账号的覆盖范围内，无论该员工是否出现在新文件中，旧有效备用记录都标记为“已覆盖”并退出计天。不新增业务记录表，不恢复旧 `SICK_REGISTER` 权限。

缺勤登记的文件记录、「我的登记记录」和月度分数明细仍可查看已覆盖的病假历史；界面将这些记录默认折叠到「已覆盖病假」区域，展开后可逐条查看。折叠只改变显示，不删除历史记录，也不改变计分口径。

预检令牌仅属于上传者，最长有效 20 分钟；缓存最多保留 8 个、源文件内容总计最多 40 MB，容量满时会提前淘汰最早的预检。成功提交后立即清除令牌。预检缓存保存在服务进程内存中，仅在单个服务进程内有效：服务必须以单进程运行（启动 uvicorn 时不要加 `--workers`），服务重启或多进程部署都会使令牌失效。令牌失效时，提交返回 400、未匹配文件下载返回 404，提示“预检结果已失效（超时、服务重启或被较新的预检挤出），请重新上传文件预检”。文件过大返回 413。请勿把源文件、预检令牌或导出的未匹配文件提交到 Git。
