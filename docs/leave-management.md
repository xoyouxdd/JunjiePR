# LOA 与月度病假事务导入

本页说明当前版本的两条不同流程。LOA 是长期病假期间，按整月排除计分；月度病假事务导入是 HR 的 `.xls` 文件明细，不等同于 LOA。旧人工病假登记接口保留历史兼容，但当前生产角色均不具备 `SICK_REGISTER` 权限，主管导航也不再显示该入口。

## 权限与范围

| 功能 | 权限 | 当前角色 |
|---|---|---|
| LOA 登记、补结束日期、撤销 | `LOA_REGISTER` | TA GSM、GSM、AM、OM、景点圈 HR |
| 月度病假事务预检、提交、未匹配文件下载 | `SICK_LEAVE_IMPORT` | GSM、景点圈 HR、系统管理员 |

LOA 员工搜索允许上述有登记权限的账号查找全部在职员工，不受其日常 HR 管理景点圈范围限制。病假导入的员工匹配仍按导入账号的员工范围检查，未匹配的明细不会覆盖系统记录。`GET /api/accounts/reset-targets` 仅服务于有 `PASSWORD_RESET` 权限的账号选择重置对象，原角色与目标范围规则不变。

## LOA 规则

- 入口为「LOA登记」。先按姓名或员工号选择员工，再登记进入日期；可在以后补填结束日期。历史记录可填写原因后撤销。对应接口是 `GET /api/loa-periods`、`POST /api/loa-periods` 和 `DELETE /api/loa-periods/{id}`。
- LOA 与自然月只要有一天交集，该员工整月的全勤、认可和扣分记录保留，但不参加当月综合分及小组汇总。统计页在 `loa_rows` 中另列人员，Excel 导出新增「LOA明细」。
- 起止日期不能反向、不能与已有 LOA 重叠。每次登记、补结束日期或撤销，只对排除状态实际发生变化的月份做月结检查和全勤重算，并写审计记录。因此开始月已月结时仍可补结束日期，但若结束日期使某个已月结月份恢复计分则拒绝；撤销会影响该 LOA 覆盖的全部月份，其中任一已月结则拒绝。未填结束日期的 LOA，覆盖范围计到当前月（及该员工已存在考勤记录的最晚月份）。

## 月度病假事务导入

1. 在「病假导入」上传 HR 导出的 Excel 97–2003 `.xls` 文件，大小不超过 10 MB（10×1024×1024 字节）。`POST /api/sick-leave-imports/preview` 核对事务区和总数区（区块标记「事务:」「总数:」，全角冒号亦可）、单一自然月、源 ID 去掉首位后的 7 位员工号、姓名、在职状态、权限范围及 LOA 日期。源 ID 为 8 位数字；丢失前导 0 的 ID（无论存成数字格式还是文本，如 `1727264`）会左补 0 到 8 位后再匹配，补位后仍须通过姓名核对，对不上的进入未匹配明细；超过 8 位或含非数字字符的行记为阻断错误。事务区与总数区按归一化后的同一源 ID 对账，时数须为大于 0 的 4 小时倍数。
2. 查看匹配、未匹配和 LOA 保护明细；未导入的人员及 LOA 保护明细可通过 `GET /api/sick-leave-imports/{token}/unmatched-file` 下载标红文件。只有预检通过且有匹配记录时才可提交。
3. 确认后调用 `POST /api/sick-leave-imports/commit`。匹配员工同月的旧有效病假（人工登记、违规病假登记及旧月度文件导入）统一标记为 `covered`，再写入新明细并重算全勤；旧记录保留历史，但不再参与病假计天。LOA 不会被覆盖。提交前重新核对 LOA，若预检后出现日期冲突则返回 409，必须重新上传预检。

`GET /api/sick-leave-imports/records` 单独列出月度文件导入的病假及其覆盖状态；「我的登记记录」保留人工登记历史，不混入新的月度文件记录。

预检令牌仅属于上传者，最长有效 20 分钟；缓存最多保留 8 个、源文件内容总计最多 40 MB，容量满时会提前淘汰最早的预检。成功提交后立即清除令牌。预检缓存保存在服务进程内存中，仅在单个服务进程内有效：服务必须以单进程运行（启动 uvicorn 时不要加 `--workers`），服务重启或多进程部署都会使令牌失效。令牌失效时，提交返回 400、未匹配文件下载返回 404，提示“预检结果已失效（超时、服务重启或被较新的预检挤出），请重新上传文件预检”。文件过大返回 413。请勿把源文件、预检令牌或导出的未匹配文件提交到 Git。
