# 月度全勤勋章（本地开发）

## 入口与权限

不增加导航页面。在现有「缺勤登记」页面下方核对、发放；员工首页展示荣誉卡、历史月份与累计次数，并可在原页面查询同事已获勋章；组员记录展开详情也展示已获勋章。

- 全员导入：复用现有全局 `SICK_LEAVE_IMPORT` 账号及最高管理员权限。景点圈 HR 不能确认全员数据完整。
- 圈确认发放：复用现有 `HR_CIRCLE` 的所属圈权限；最高管理员可管理全部圈、代发、纠错。
- 最高管理员可以核实原账号创建日期、重新核对月份归属快照或修正某个人的月份归属，均需填写原因。
- 查看同事只返回正式月份的有效勋章与次数，不返回请假、未获得及撤回原因。本人详情和圈管理名单提供对应私密信息。临时轮岗访问身份不能使用员工勋章接口。

## 时间与试用隔离

- 2026-11、2026-12 可在管理端导入、确认、发放、调整；始终不向员工展示或通知，不进入正式累计。GSM、AM、OM 和最高管理员可以只读查看已确认的试用获奖名单，不显示请假明细或未获奖原因。
- 2027-01 起正式评定；2027-02-01 之后导入并确认 1 月完整请假数据，再由各圈管理员分别发放。
- 试用和正式月份均须结束并完成相应范围的月结，且全员数据已确认完整、相关异常已处理，才能发放。重新打开月结会暂停相应获奖结果的展示；正式勋章通知也会暂时隐藏，已发记录保留。
- 员工端正式内容自 2027-02-01 开放，后端过滤试用月份，不能通过修改前端时间获得试用数据。

## 评定规则

依据当月最终有效记录评定。任何假别、任何正时数的有效请假，以及有效违规病假、迟到、早退、早打卡、晚打卡和未打卡均影响全勤。正常休息和调休不影响；审核中或已作废的考勤声明不按生效记录评定。勋章不改变计分。

原有导入代码只处理三类病假并按既有计分口径校验。勋章使用独立数据表读取其他请假事务，不扩大病假扣分范围。常规含「假」字的工资代码计入请假，已明确的正常工作、休息、节假日和调休代码排除。未知缩写、非标准代码不能直接跳过：由统一导入管理员在原页面填写依据、明确分类为请假或正常事务，再重新替换导入原文件。标准请假代码不能通过此入口改为正常事务。分类变更会生成新的阻断版本，使相关月份重新待核对，保留原批次和已发勋章，阻止旧预览继续发放。

事务区与总数区按归一化工号、假别对账；法定病假和全薪病假合并核对病假时间总计。请假事务漏行、总数不一致、工资代码缺失、负数或非数字时数，均形成阻断异常。总数区单独出现未知代码时也要分类，不能因事务区缺行就当作无请假。请假允许任意正时数，不套用计分导入的四小时倍数限制。撤销、作废、负时数调整等应在源数据中整理为最终有效记录。

正常的全局月度缺勤文件提交，会在同一事务中同步勋章请假数据，但不会确认完整或自动发放。也可使用勋章区域的独立补导，不改变既有计分和月结。

独立导入支持追加和替换整月：先预览新增/移除/异常数量，确认后提交；文件摘要和旧版本号防止使用过期预览。追加按员工身份、日期、假别和时数去重。整月无人请假也需通过该月正常事务证明月份，再确认完整；空文件不可清除记录。

## 人员资格

- 有正式员工账号和工号，归属明确；管理专用账号不参与员工荣誉。
- 从原账号创建后的下一个自然月参与，1 日创建也不例外。老员工补建账号同样执行。
- 原账号创建时间独立留档；同一员工删除重建账号保留资格和勋章。系统既有工号变更继续沿用同一员工 ID。
- 仅重建登录凭据不改变在职周期，仍沿用原日期；项目现有「删除人员（留档）→重新注册」是正式离职、返聘流程，按返聘下月重新参与，不能因工号相同而跳过等待。已分别通过凭据重建测试及真实离职、返聘接口验证。
- 月中离职不参与；离职日按最后在职日理解，最后一天仍在职且覆盖完整月份可以参与。
- 账号停用不等同离职。无法登录不影响已获勋章保存。
- 离职返聘保留历史荣誉，从重新入职后的下一个自然月恢复参与；利用现有在职周期历史评定过去月份。
- 历史账号原日期缺失时列为待处理，由最高管理员核实，不能推测为全勤。
- 同一工号的七位与单个前导零档案碰撞时，即使导入文件没有请假，也暂停相关身份评定，不能重复发放。异常工号格式同样待核实；不自动合并或覆盖档案。

## 圈归属与发放

以月底所属圈负责，检查整个月全员请假数据。优先读取现有月份组织快照，并结合已完成跨圈调动、人员修改审计及在职周期还原历史归属。首次确认数据完整时保存月份归属快照；后续调圈不自动改写历史。证据不足时由最高管理员核实修正。

1. 全局管理员导入并确认该月全员数据完整。
2. 各圈分别核对拟发放、未获得、不参与、待处理名单。
3. 明确归属的异常只阻断相应圈，归属不明的请假异常阻断全部圈。工号与姓名冲突视为真实身份未明确，不能单凭工号放行其他圈。
   源表异常明细仅全局导入管理员及最高管理员可见；圈管理员只看到脱敏的阻断提示，已定位本圈工号的异常可提示对应本圈员工，不能展示未经核实的源表姓名与假别。请假匹配异常与人员名单共用同一套历史圈归属还原，避免当前调圈导致原圈问题漏查或向新圈泄露。
4. 圈管理员确认窗口展示月份、圈、人数及变化，确认后在单一数据库事务内发放。
5. 本圈无人符合也可确认完成；三个圈互不等待。
6. 重复提交不重复发勋章、不重复通知；事务失败整体回滚，可在重新核对后重试。

预览后请假版本或人员资格变化，旧提交会被拒绝。完整性确认与各圈发放为独立步骤。待办进入现有行动中心，不自动发放。

## 补录、纠错与展示

补导使数据重新进入待确认完整。未发放圈更新预览；已发放结果保持，发生评定结果变化的圈显示待调整，需填写原因后确认补发或撤回。结果未变的圈无需再次确认，不重复通知。跨圈历史纠错由最高管理员处理，同一员工同一月份最多一枚勋章。

历史首次补发指正式月份早于上一个完整自然月、且该圈从未确认过该月评定，须最高管理员确认；上月常规发放由各圈负责。已确认月份后续补录、补发和撤回仍由相应圈管理员按原权限确认。11、12 月管理端试用不受此首次历史补发限制。

正式发放或调整在同一事务中保存站内消息。员工查看后可确认已读；通知读取失败不影响勋章本身。发放时间、操作人、来源版本、结果及调整原因保留审计，页面提供本圈操作记录。

员工消息列表、行动中心未读数和已读接口均过滤试用月份及未结束的未来月份。即使本地测试曾写入试用消息，也不会进入员工端；上线前的已有前端内容也会被清空。

个人只公开有效月度勋章和累计次数；补发增加、撤回减少。本人能查看最终评定依据和私密消息，如有异议联系本圈管理员。调圈后新圈管理员不自动取得原圈月份的请假详情。没有公开排行榜、灰色未获得勋章、连续等级或年度勋章。

## 本地验证

### 十二月节气图案与静态资源

员工收藏、月份详情及管理员当前月样式预览已使用获批的十二款 Imagegen 图案。页面只展示纯勋章图案；月份、累计次数、发放日期均取自系统数据，寄语为「每一份坚持，都值得被看见」，评定规则可另行展开。原海报中的示例数字和日期未进入运行时图片。

- 资源目录：`backend/app/static/images/attendance-medals/seasonal-521cf58ca25a/`，每月缩略图和展开图各一张，共 24 张 WebP；图案按所属月份选择，与发放月份无关，跨年份复用。
- 12 张缩略图合计 165,424 字节（约 162 KiB），全部图片合计 1,192,622 字节（约 1.2 MB）。单张缩略图小于 24 KB，展开图小于 100 KB。
- 缩略图使用原生懒加载、异步解码和低优先级。大图仅在展开时请求；同一收藏区域只展开一枚，收起恢复缩略图。重复打开使用浏览器缓存，不追加业务 API 请求。
- 静态图片使用带内容摘要的版本目录，响应为正确的 `image/webp`，缓存 `public, max-age=31536000, immutable`，保留 ETag 条件请求。此缓存策略只作用于公开图案，不作用于员工、请假或消息 API。
- 加载失败显示内置图标和真实荣誉文字，不自动重试或启动图片生成。上线前员工端不请求这些图案，11、12 月试用记录的既有隔离不变。
- `scripts/build_attendance_medal_assets.py` 仅用于离线准备素材，不由服务器导入或执行。原始海报留在 `output/`，运行时不调用 Imagegen，不读取原海报，也不新增数据库、后台任务或业务接口。
- 后续改图应重新离线生成内容版本，禁止原地覆盖已发布的版本目录，以免长期缓存出现旧图。

本轮验证：`test_attendance_medal_assets.py` 检查图片预算、类型、长缓存、ETag 和静态请求零 SQL；`attendance_medal_art_ui.cjs` 检查十二色、动态文字、按需加载、缓存复用、失败回退、路径前缀和上线前隔离；原有 `attendance_medals_ui.cjs`、`personal_center_ui.cjs` 检查相关入口与角色流程。

后端测试使用临时数据库，浏览器测试使用合成 API 数据，不导入或发放真实员工数据。

定向测试：`test_attendance_medals.py`、`test_attendance_medals_lifecycle.py`（真实留档与重新注册接口）、`test_sick_leave_import.py`、`test_operations_action_center.py`，以及 `attendance_medals_ui.cjs`（含工资代码分类、脱敏及上线前内容清空）。账号留档、圈审计、既有荣誉和缓存模块的原有回归按实际变更依赖选择，不默认全量重跑。

浏览器测试要求 Node 能解析 Playwright，Edge 与匹配版本的 WebKit 可用。截图输出至 `output/attendance-medals-local/`。本地开发及定向验证不代表已推送、打包或正式上线。
