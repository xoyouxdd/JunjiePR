# 本人认可多条登记

CM/TR和本职CM/TR的TA主管在本人登记入口，默认一条，最多五条。
日期、类型、内容、发生景点、签卡人逐条填写；仅照片共用。
主管本人登记、管理人员代录和POC专用入口不变。

## 提交与存储

`POST /api/recognitions/batch` 使用multipart：entries为JSON数组，image为一张图片，idempotency_key为提交标识。
前后端均限制1～5条，服务端禁止指定其他员工，逐条复用原登记验证、日期身份分值、历史景点快照、月结限制及复核路由。
图片在获得数据库写锁前完成暂存；全部记录、附件关联、逐条审计、提交回执同一事务提交，失败回滚并清理本次图片。
同批及既有同日重复登记仍须确认，表扬信每月一次限制保持不变。已提交请求重试返回原记录；同标识不同内容拒绝。

认可业务仍为独立RecognitionRecord，不新增业务表。照片为一份StoredFile，各条使用独立RecognitionAttachment关联。
旧库通过一次性schema migration移除附件file_id单列唯一约束，保留附件ID、所有字段、外键、每条附件类型唯一约束和查询索引。
附件权限检查全部关联记录，水印、下载审计不变；撤回其中一条保留其他条目的照片。

## 计分和查询

本人提交仍为pending；逐条复核。安全、礼仪、效率、演出、包容按原生效日期和员工/月/类别5分上限计算实际计入分值。
复核在读取记录及剩余额度前获取数据库写锁，串行完成额度计算和状态提交，防止并发复核突破上限。
主页、待办、统计及导出继续按独立记录计算；原始分值、实际计入分值及未封顶排名规则不变。

相关回归：test_self_recognition_batch.py、self_recognition_batch_fields.cjs及原单条/复核/统计/导出测试。
