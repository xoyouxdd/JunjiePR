# iPhone UC认可图片读取复查

本地候选版本：2026.10.20.4。用户反馈时间为2026-10-20 18:23，截图为本人批量登记，两条认可共用一张照片，提示“图片未成功读取”。用户补充：选图后显示文件名，只提交一条也有相同报错。

## 已确认与未确认

- 原实现只读取首个有文件列表的控件的 `files[0]`，缺少 `FileList.item()` 和原生表单文件后备读取。
- 文件名、正数大小等前端条件不满足会出现该提示；单条入口服务器未收到图片也可能映射为同样提示。截图不能证明具体命中了哪一处。
- 批量登记此前没有单条入口的 `image_client_ready` 标记，统一校验异常诊断也没有覆盖 `/api/recognitions/batch`。
- 免密连接失败后，用户在本机交互输入密码完成只读核对。18:35:21（北京时间）在线健康正常，版本2026.10.20.3；账号在18:21:50登录，18:18—18:30没有成功认可登记或该入口的失败审计。
- 近期访问日志存在批量认可HTTP 422，旧版该入口未写入缺图诊断，且访问日志没有逐请求时间和账号；这些日志不能单独证明哪条属于18:23的尝试，不能确定图片在哪一步丢失。
- 本地兼容模拟与服务器无成功记录都不等于UC真机修复已确认。

## 本地修改

1. 共用选图读取函数依次检查原始文件列表、标准item访问与原生表单中的同名文件字段。选图提示和实际提交使用同一个读取函数。
2. 选图成功时在当前页面内存保留同一文件对象；只在该输入的选择标识未变时使用。新选择先作废旧对象，清空、切换照片入口或提交成功后清理；未写入localStorage或其他持久缓存。
3. 后备路径只接受真实、非空、有名称且具备Blob切片能力的文件。路径字符串、空文件和不可用对象不能代替图片；不请求本地路径，不生成替代图片。
4. 批量入口补齐上传就绪标记与接收失败诊断，区分前端已选但服务器缺失图片的情况。审计仅沿用浏览器分类、字段名、就绪标记等信息，不加入照片内容或文件名。
5. 保留上传原字节、权限、原图片格式/大小/像素校验、计分、复核、原子事务、幂等与失败保留内容规则。

原生表单读取文件的标准依据：[MDN FormData构造器](https://developer.mozilla.org/en-US/docs/Web/API/FormData/FormData)。这是标准API能力依据，不是UC问题根因的证明。
