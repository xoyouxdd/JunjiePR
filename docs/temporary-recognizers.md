# 临时主管认可资格

员工管理的折叠区域「临时主管认可资格」由已有员工管理权限的账号操作，景点圈HR仅管理本圈。可为在职、账号启用、有有效景点圈的CM/TR多选本月日期，填写原因并确认；支持本月历史日期及未来日期，非连续日期独立生效。

资格独立存储，不写入本职、代理职务、小组或角色权限。本人仍按CM/TR计分和使用原有功能，不获得TA主管的代录、扣分、复核或带组权限，不产生代理职务到期提醒。

认可人列表和提交均按认可发生日期核验资格。资格标签为「临时主管认可资格」，分值复用该日期的TA主管配置；单条、批量本人登记及已有权限的管理代录复用相同规则。原审核、本人不可认可本人、主管认可人限制、重复提醒、月度上限和月结保护保持。记录保存资格标签、认可分值及认可人本职快照，资格到期后可补登记有效日期，不按今日身份覆盖历史资格。

当前月份可调整日期，未来月份不能预置。已有真实代理职务的日期不能重复授予。资格保存有并发版本检查和事务保护；已有任何认可引用资格的日期禁止直接取消，需核对关联记录并按更正流程处理。补授资格不会重算已有认可。授权、调整、取消保留员工审计记录。

数据表 `temporary_recognition_qualifications` 每人每日唯一。沿用启动时 `Base.metadata.create_all` 的新表创建流程，不修改既有表结构。界面按需加载本月资格；历史月份数据保留用于认可日期核验，不在本月编辑器中修改。

认可记录的角色代码快照保存实际CM/TR身份；TA主管仅用于选取分值配置。临时资格签发人不进入主管认可排名或对应导出，旧版已保存为TA主管代码的资格记录按资格标签排除。实际主管代录该认可仍按原口径统计其代录贡献。

同一档案重新入职时，旧周期在本次入职当天及以后的有效资格自动取消，记录操作人、原因及重新入职审计。此前日期的历史资格和认可记录保留，供历史补登和核对；新周期需重新授权。资格取消与重新入职在同一事务中，注册失败一起回滚。

验证：`tests/test_temporary_recognizers.py` 覆盖离散日期、权限隔离、计分复核、单条/批量登记、历史补登、撤销保护、范围与月结限制；`tests/temporary_recognizers_ui.cjs` 覆盖桌面/窄屏多选、筛选、确认提交及已保存日期回显。
